# Android TV

Orbit's desktop player can't move unchanged into Tauri's Android WebView, so on Android TV video plays in a native player screen (a SurfaceView, with Media3). Browsing, settings and library logic stay in TypeScript/Rust; a libmpv backend could come later if measured compatibility and feature parity justify its maintenance. A native player costs a second controls implementation and a native event bridge, but avoids making transparent WebView composition the foundation of playback. Orbit still bundles no content or content addons.

## Where it stands (Google TV emulator, API 36, x86_64)

A complete playback session works on the emulator: browse, search, install an addon, play, use the remote in the player, leave with Back, find it in Continue Watching and resume where it stopped; at the end of an episode the next one counts down and plays; live TV plays and surfs with channel up/down. Not yet tried on a real TV.

| Area | State |
| --- | --- |
| Shell | `src-tauri/gen/android` is committed; the Rust side builds for Android with the desktop-only pieces gated (`target_os = "android"`). Desktop checks stay green. |
| Secrets | `SecureStorePlugin.kt` seals each secret under an AES-256-GCM key held in the Android Keystore (fresh IV, the entry's name as associated data); `keychain.rs` uses it on Android. Its plugin refuses WebView calls. Android backup and device transfer are off, because the Keystore key can't follow the data. |
| HTTPS | rustls' platform verifier checks certificates with Android's trust store; `TlsInit` hands it the app context before Rust starts. |
| Remote | D-pad, Enter and the media keys reach the page as on a PC, from the first press (the WebView takes Android's focus on start and resume). Back is Orbit's Back (closes overlays, then goes back through pages) and only leaves the app from the first page. In the player, channel up/down and next/previous go to the page (channel surfing, next episode). |
| Video | `NativePlayer.kt`: a Media3 player screen. Rust resolves the address as on a PC and hands it over in-process (never in an Intent); its state comes back to the page as mpv's events, so resume, watched marks and next-up work; at the end it steps aside so the end screen or the next episode's countdown shows. Addon subtitles are fetched and cleaned in Rust and handed over as contents. Pause and seek (the phone remote) reach it. It opens only http/https, the data: subtitles Rust hands over and the one downloaded file Rust resolved, like mpv's protocol whitelist; a sign-in header doesn't follow an https-to-http redirect. Media3's own controls; mpv-only settings (picture, sound filters, subtitle styling, sync) report that they're unavailable. |
| Launcher | Orbit's icon (adaptive from Android 8) and a 320×180 TV banner; leanback launcher entry; no touchscreen required. |
| Settings | Window, tray, Discord, external-player rows and the whole Picture & Sound page (all mpv) are hidden on Android, in the palette too; hints name Android instead of Windows. Playback has an opt-in "Match the TV's refresh rate". |
| Outside control | A Media3 `MediaSession` (media3-session) for the player screen: "Hey Google, pause", a TV's own remote over HDMI-CEC and Bluetooth remotes reach it, and Android's Now Playing shows the title and episode line the page gives the phone remote. Next and previous from outside go to the page as the remote's own keys do, so the next episode or channel is Orbit's choice. |
| Audio formats | Jellyfin's build of Media3's FFmpeg decoder (`org.jellyfin.media3:media3-ffmpeg-decoder`, GPL-3.0, version matched to Media3; FLAC, ALAC, MP3, AAC, AC-3, E-AC-3, DTS, TrueHD) decodes audio that neither a platform decoder nor passthrough takes. Platform decoders and passthrough still come first. About 1.5 MB per ABI. |
| Home screen | Settings → Playback → "Show Continue Watching on the TV's home screen" (off by default) puts Orbit's Continue Watching in the system's Watch Next row (androidx.tvprovider). One list for the TV, which everyone at it sees: the active profile's titles only while it has no PIN; a PIN, the setting turned off or an empty list clears it. Entries hold the public name, the title's https picture (never an episode still, which could spoil it, and never Jellyfin/Plex art, which needs a sign-in) and Orbit's title id. Picking one opens Orbit, which plays it only if the profile that comes up has it in its own list. One the person removes from the row stays removed while it's in Orbit's list. Any app can send that intent to Orbit; the worst it can do is start a title from the current profile's own Continue Watching. Checked on the emulator by reading the provider back, not on a real launcher (Google TV shows no rows without a Google account). |
| Player extras (ideas from NuvioTV, CloudStream, Just Player, ARVIO) | Audio attributes and focus; decoder fallback; a live stream behind its window rejoins it and dropped connections retry twice before the page hears; smaller buffers on low-memory boxes; Settings' audio/subtitle languages and subtitle look (size, colour, shadow/box/outline, position, bold); Skip intro and Next up buttons over the video; refresh-rate matching. |
| Ranking | Android reports its hardware decoders, HDR kinds and screen resolution; sources it can't decode go last, unshowable HDR gets no bonus, 4K on a 1080p screen counts against a source ("Why?" lines say so). |
| Search | A microphone on Search opens Android's speech prompt (no microphone permission); android.intent.action.SEARCH opens Search with its query. |
| Downloads | Saved under the app's own storage (`Android/data/io.github.fusnk.orbit/files/Download/Orbit`), kept until Orbit is uninstalled, and play offline in the native player. |
| Trailers | No yt-dlp on Android: the Trailer button opens the YouTube app (only a checked 11-character id is handed over). Banner trailers don't play there. |
| Failures | When no source plays, the player screen steps aside so Orbit's message and its buttons show. |
| Larger, later | Seek thumbnails from Jellyfin/Plex, Dolby Vision profile 7 fallback. |
| Not yet | Jellyfin/Plex external subtitle files (they need the sign-in, so fetching them for Media3 needs its own path), track menus in Orbit's style, live TV with a real provider on a device, Next Up before the credits (it shows only at the end), external players, Watch Next on a real launcher, signed release builds, ARM64 hardware testing. |

### Build and run on the emulator

Tauri links the built library into `gen/android` with a symbolic link, which Windows only allows in Developer Mode (Settings → System → For developers). With it on, `pnpm tauri android dev` and `pnpm tauri android build --debug --apk --target x86_64` work as documented. Without it, build the library with Tauri (it fails only at the link step), copy `<target>/x86_64-linux-android/debug/liborbit_lib.so` into `src-tauri/gen/android/app/src/main/jniLibs/x86_64/`, then run `gradlew assembleX86_64Debug -x rustBuildX86_64Debug` in `src-tauri/gen/android` and `adb install -r` the APK from `app/build/outputs/apk/x86_64/debug/`.

The Google TV image won't skip its own setup without a Google account; for a test emulator, `adb shell settings put secure user_setup_complete 1` and `adb shell settings put global device_provisioned 1` reach the home screen. To test with the example addon, run `node examples/addon/server.js` and `adb reverse tcp:7000 tcp:7000`, then install `http://127.0.0.1:7000/manifest.json` in Orbit. In a debug build, the WebView's DevTools are on `adb forward tcp:9555 localabstract:webview_devtools_remote_<pid>`.

Release builds don't allow plain `http` (`usesCleartextTraffic` is off outside debug), which Media3 needs for IPTV providers and media servers on the home network, as mpv has on a PC. That needs a decision (a network security config allowing it for playback) before a release build. Debug builds allow it.

## Why a native player

Tauri 2 mobile wraps the existing frontend/Rust application in a generated Kotlin/Gradle Android project. Native integrations use Kotlin mobile plugins registered from Rust. That preserves substantial browsing and protocol code, but does not supply Orbit's desktop libmpv window integration. ([Tauri mobile plugins](https://v2.tauri.app/develop/plugins/develop-mobile/))

| Video approach | Benefit | Cost and recommendation |
| --- | --- | --- |
| SurfaceView behind a transparent WebView | Reuses Orbit's TS player controls | Requires custom view hierarchy, transparent composition, input routing and lifecycle synchronization. No drop-in Tauri underlay was verified. Prototype only after native playback succeeds. |
| Native player Activity with SurfaceView | Owns decoder surface, audio focus, lifecycle and remote controls together | Requires native controls and an event/session bridge. Recommended foundation. |
| Media3/ExoPlayer backend | Platform codec integration and established Android lifecycle APIs | Device-dependent formats and less mpv/libass parity. Recommended initial device proof. |
| Android libmpv backend | Closest match to desktop mpv properties, events and subtitle rendering | Native ABI builds, JNI ownership and hardware-decoding validation. Candidate second backend. |

SurfaceView is the preferred starting surface for power use, frame timing, supported HDR and full display resolution on TVs whose UI resolution is lower. A surface placed above the WebView would obscure controls; an underlay requires deliberately coordinated stacking. ([Android surface guidance](https://developer.android.com/media/media3/ui/surface))

**mpv-android is an application, not an upstream importable AAR.** Its Kotlin wrapper loads native libraries and exposes JNI lifecycle, commands, properties and surface attachment. A future Orbit module would need a maintained native build or an audited provider, not an invented AAR dependency. The wrapper is MIT, while the current FFmpeg build enables GPL/version3 and mpv has its own native licensing requirements. Orbit's GPL-3.0-or-later license does not replace an audit of distributed binaries, corresponding sources, build flags and notices. Media3 is Apache-2.0; optional native extensions require separate review. ([mpv-android](https://github.com/mpv-android/mpv-android), [JNI wrapper](https://github.com/mpv-android/mpv-android/blob/master/app/src/main/java/is/xyz/mpv/MPVLib.kt), [FFmpeg build](https://github.com/mpv-android/mpv-android/blob/master/buildscripts/scripts/ffmpeg.sh), [mpv copyright](https://github.com/mpv-player/mpv/blob/master/Copyright), [Media3](https://github.com/androidx/media))

Media3 relies principally on platform decoders. Container support does not establish codec support, and subtitle format support does not establish full ASS styling parity. HDR10, HDR10+ and Dolby Vision must be tested by device, firmware, content profile/container and HDMI/display chain. **Do not promise universal Dolby Vision passthrough.** HDR video decoding/display is distinct from encoded audio passthrough; both need separate tests. Software decoding is not a substitute for reliable 4K hardware playback. ([Supported formats](https://developer.android.com/media/media3/exoplayer/supported-formats), [Android HDR pipeline](https://source.android.com/docs/core/display/hdr))

Rust should create an opaque playback session and transfer private URLs/headers through the native bridge, never exported intents or logs. Native backend events must drive resume, watched marks, subtitle selection and completion. For libmpv, mpv remains the source of truth; Media3 would need an explicit backend adapter and must not report unsupported mpv-specific settings as applied.

ARVIO demonstrates Media3 with explicit control focus and lifecycle handling under Apache-2.0. Its focus restoration accounts for virtualized targets becoming attached. NuvioTV is a Kotlin/Compose TV project under GPL-3.0 and currently includes both Media3 and libmpv infrastructure; it is not merely an ExoPlayer example. Borrow the ideas of capability boundaries, surface ownership and stable focus restoration, not implementations or device heuristics. ([ARVIO](https://github.com/ProdigyV21/ARVIO), [ARVIO player](https://github.com/ProdigyV21/ARVIO/blob/main/app/src/main/kotlin/com/arflix/tv/ui/screens/player/PlayerScreen.kt), [ARVIO focus](https://github.com/ProdigyV21/ARVIO/blob/main/app/src/main/kotlin/com/arflix/tv/ui/focus/ArvioDpadFocus.kt), [NuvioTV](https://github.com/NuvioMedia/NuvioTV), [Nuvio mpv surface](https://github.com/NuvioMedia/NuvioTV/blob/dev/app/src/main/java/com/nuvio/tv/ui/screens/player/NuvioMpvSurfaceView.kt))

## TV navigation must work without touch

Orbit's `src/app/spatial.ts`, remappable actions in `src/lib/keymap.ts`, and Couch/TV settings in `src/theme/looks.ts` provide a useful foundation. Verify Android WebView delivery of D-pad directions, center/Enter, media buttons and Back. Bridge missing events into the existing action layer without double activation. Focus must remain separate from activation; only explicitly activating an input should open the IME. Every dialog, source chip, track selector and slider must be remote-operable. ([TV controllers](https://developer.android.com/training/tv/get-started/controllers))

Back should dismiss the IME, dialog, panel and player in order, then navigate views and eventually return to the launcher; Home belongs to the OS. Restore focus after loading, Activity resume and virtualized-row attachment. Test from a couch at 720p/1080p/4K UI densities, including overscan, readable subtitle/settings sizes, focus contrast, RTL, reduced motion and low-memory resume. Android-specific Couch defaults must not change desktop preferences. ([TV navigation](https://developer.android.com/training/tv/get-started/navigation))

Watch Next and home-screen channels belong in a later opt-in phase. Publish public metadata/art and opaque Orbit deep links, not playback URLs or tokens. Recheck profile PIN/content restrictions when opening, remove stale entries when profiles/history change, and respect spoiler/privacy/history-pause choices. Android TV providers require channel/program integration and launcher-specific approval/behavior testing. ([TV channels](https://developer.android.com/training/tv/discovery/recommendations-channel))
